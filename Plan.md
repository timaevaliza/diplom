# План автоматизации тестирования веб-сервиса «Путешествие дня»

## 1. Перечень автоматизируемых сценариев

### 1.1. Сценарии оплаты по дебетовой карте

#### Позитивные сценарии:
- **Заполнение формы валидными данными карты** (карта `4444 4444 4444 4441`). Ожидаемый результат: уведомление «Успешно. Операция одобрена Банком», в БД статус `APPROVED`.
- **Заполнение формы данными карты, которая отклоняется банком** (карта `4444 4444 4444 4442`). Ожидаемый результат: уведомление «Ошибка! Банк отказал в проведении операции», в БД статус `DECLINED`.

#### Негативные сценарии (валидация формы):
| № | Поле | Действие | Ожидаемый результат |
|---|------|----------|---------------------|
| 1 | **Номер карты** | Ввод пустого поля | Сообщение «Поле обязательно для заполнения» |
| 2 | **Номер карты** | Ввод номера из 15 цифр | Сообщение «Неверный формат» |
| 3 | **Номер карты** | Ввод номера с буквами | Сообщение «Неверный формат» |
| 4 | **Месяц** | Ввод значения `00` | Сообщение «Неверный формат» |
| 5 | **Месяц** | Ввод значения `13` | Сообщение «Неверный формат» |
| 6 | **Месяц** | Ввод пустого поля | Сообщение «Поле обязательно для заполнения» |
| 7 | **Год** | Ввод значения `00` (истекший срок) | Сообщение «Истёк срок действия карты» |
| 8 | **Год** | Ввод значения `99` (слишком далёкий срок) | Сообщение «Неверный срок действия карты» |
| 9 | **Год** | Ввод пустого поля | Сообщение «Поле обязательно для заполнения» |
| 10 | **Владелец** | Ввод пустого поля | Сообщение «Поле обязательно для заполнения» |
| 11 | **Владелец** | Ввод цифр вместо имени (например, `12345`) | Сообщение «Неверный формат» |
| 12 | **CVC** | Ввод значения из 2 цифр | Сообщение «Неверный формат» |
| 13 | **CVC** | Ввод значения из 4 цифр | Сообщение «Неверный формат» |
| 14 | **CVC** | Ввод пустого поля | Сообщение «Поле обязательно для заполнения» |

### 1.2. Сценарии покупки в кредит

#### Позитивные сценарии:
- **Заполнение формы валидными данными карты** (карта `4444 4444 4444 4441`). Ожидаемый результат: кредит одобрен, в БД статус `APPROVED`.
- **Заполнение формы данными карты, которая отклоняется банком** (карта `4444 4444 4444 4442`). Ожидаемый результат: кредит отклонён, в БД статус `DECLINED`.

#### Негативные сценарии (валидация формы):
Аналогичны негативным сценариям для оплаты по дебетовой карте (проверка всех полей формы).

---

### 1.3. Проверка сохранения в СУБД

После каждого платежа/кредита в БД сохраняется информация:
- успешно ли совершён платёж (`status`);
- каким способом (обычная оплата/кредит);
- сумма платежа (`amount`);
- дата и время платежа (`created`);
- идентификатор транзакции (`transaction_id`).

**Важно:** Данные карт **не сохраняются** (требование безопасности).

---

### 1.4. Проверка работы с двумя СУБД

| СУБД | Действие |
|------|----------|
| **MySQL** | Все сценарии проверяются при подключении к MySQL (порт 3307) |
| **PostgreSQL** | Все сценарии проверяются при подключении к PostgreSQL (порт 5432) |

## 6. Отчёт по автоматизации

Отчёт оформляется в виде файла **`Summary.md`** и заливается в репозиторий проекта.

Содержание отчёта:
- Что было запланировано и что реализовано
- Причины, по которым что-то не было реализовано (если есть)
- Сработавшие риски
- Общий итог по времени: план vs факт с обоснованием расхождения
- Рекомендации по улучшению качества
